# Пример: read-only ревизия запутанного Next.js-сайта

Переиспользуемый паттерн из ревизии сайта с каталогом, собранного через агента-кодера.
Это пример, а не постоянное правило для других проектов.

## Ситуация

Человек собирал сайт с агентом-кодером и жаловался, что тот не видит очевидных
продакшен-проблем:

- сломанный или дублирующийся хедер/навигация;
- дубли или странный текст;
- продакшен-UI выглядит не так, несмотря на правки кода;
- слишком много истории и кода будущих фаз, из-за чего каша.

Человек просил ничего не менять, поэтому ревизия осталась read-only.

## Полезные приёмы

### 1. ТЗ/роадмап — источник продуктовой правды

Приложенный markdown-контракт оказался надёжнее PDF, извлечённого через `pdftotext`
(русский текст из PDF выходил битым). Контракт определял: первую фазу (рабочий сайт,
меню/конфигуратор, корзина, доставка, заявки, кабинет, бронь, контакты), более поздние
фазы и что исключено из первой фазы (онлайн-оплата, полная админка, SMS-логин, трекинг
статусов и т.п.).

Урок: когда извлечение из PDF плохое, а markdown/предложение есть — markdown и есть
оракул объёма.

### 2. Сначала проверь владение живым маршрутом

В проекте существовало несколько реализаций одной страницы:

- `src/app/menu/page.tsx` импортировал `MenuEditorialPage` — это и был живой `/menu`.
- `src/components/pages/menu-page.tsx` существовал, но маршрут его не использовал.
- `src/components/menu-page-content.tsx` — ещё одна старая/альтернативная логика.

Урок: агент может «чинить» мёртвые компоненты, пока не построена карта владения маршрутами.

### 3. Браузер + accessibility + текст DOM вместе

Accessibility-снимок показывал склеенный текст:

```text
С2017года— отаквариума довашейдвери.
```

А DOM `innerText` выглядел нормально:

```text
С 2017 года —
от аквариума
до вашей двери.
```

Вероятная причина: анимированные заголовки, разбитые на множество span'ов / неразрывные
пробелы. Визуально может быть приемлемо, но плохо для accessibility/SEO. Записать как
QA-находку и подтвердить визуально до правки.

### 4. Риск хедера/навигации из git-истории и кода

Признаки:

- недавние коммиты все вокруг читаемости/унификации навигации;
- глобальный `<Navigation />` на не-главных маршрутах;
- главная использует отдельный `HomeMenu`;
- старые внутристраничные панели управления всё ещё существуют и спрятаны CSS под
  `body[data-global-nav="true"]`.

Риск: тайминг гидрации/перехода/датасета body может кратко показать дубль навигации или
оставить старые контролы видимыми. Такое агент часто пропускает: каждый файл по отдельности
выглядит разумно.

### 5. Отдели скрытый код будущих фаз от утечек в продакшен

В репозитории был код ops/курьера/трекинга, но middleware редиректил или 404-ил маршруты/API
при выключенном флаге:

```ts
const REDIRECT_TO_HOME_PREFIXES = ["/ops", "/courier"];
const COURIER_API_PREFIXES = ["/api/admin", "/api/internal", "/api/courier"];
```

Это совпадало с исключениями ТЗ, но всё равно создавало нагрузку. Формулировка ревизии:
«сейчас защищено, но код будущих фаз существует и может путать агентов».

## Что сработало на выходе

Заметка-ревизия с секциями: цель/объём; текущее состояние репозитория; ветка/нетрекнутые
файлы; риски владения маршрутами/компонентами; конкретные видимые находки; скрытый код
будущих фаз; рекомендованные волны (карта read-only → визуальный QA → правки только после
одобрения).

## Формат находки

```text
[Страница]
Что вижу:
Почему важно:
Доказательство:
Вероятные исходники:
Приоритет:
Нужно ли разрешение на правку:
```
