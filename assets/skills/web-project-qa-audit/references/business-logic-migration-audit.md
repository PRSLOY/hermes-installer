# Проверки бизнес-логики и миграций

Для read-only ревизий, где есть деньги, смешанные валюты/единицы, исторические курсы,
графики и воспроизводимость миграций.

## Трассировка размерностей

Собери компактную матрицу до того, как судить об арифметике:

| Этап | Поле | Заявленная единица | Реальная единица источника | Конверсия |
|---|---|---|---|---|
| Вход API | `price*` | из имени/схемы | payload | нет/явная |
| Сопоставление | валюта позиции | нативная | строка БД | правило фильтра |
| Хранение | `buy_price` / `sell_price` | конвенция схемы | значение запроса | присваивание |
| Калькулятор/вьюха | операнды | валюта ветки | хранимые значения | делитель/курс |
| UI | форматированное | валюта отображения | результат API | форматирование |

Сопоставление, игнорирующее валюту/единицу, может направить корректно названный минорный
payload в позицию, чьё поле хранения трактуется в другой единице.

## Минимальный repro

Бери конкретные значения, где путаница единиц очевидна:

```js
const buyMinor = 1000n;              // минорные единицы одной стороны
const sellMinor = 5_000_000_000n;    // минорные единицы другой стороны
const correct = Number(sellMinor) / 1e9 * 3 - Number(buyMinor) * 0.013;
console.assert(correct === 2);
```

Для исторических графиков сравни историческую конверсию с конверсией по текущему курсу:

```js
const usd = 42;
console.assert(usd / 3 === 14); // исторический курс
console.assert(usd / 7 === 6);  // переоценка по текущему курсу — другая семантика
```

Запускай inline или существующими фокусными тестами; файлов в read-only ревизии не создавай.

## Проверка дублирующих реализаций

Сравни калькулятор приложения, SQL-вьюху, обработчики импорта/обновления, аналитическую
агрегацию и тесты. Зелёные тесты одной реализации не валидируют другую. Противоречие с
детерминированным repro — подтверждённый дефект.

## Классификация исторического fallback

Если при сбое запроса подставляется текущий курс вместо исторического — зафиксируй:

- виден ли fallback вызывающему;
- сохраняется ли как «историческая правда»;
- маркируют ли графики это как переоценку по текущему курсу;
- фиксируют ли тесты это поведение намеренно.

Fallback может работать «как задумано» и всё равно быть дефектом бизнес-данных, если
происхождение потеряно.

## Осуществимость миграций

Сравни: SQL-файлы миграций; записи журнала; снапшоты; скрипты пакета; задокументированные
ручные раннеры; объекты, объявленные как существующие извне (вьюхи/расширения/функции).

Статическое расхождение доказывает фрагментацию workflow, но не обязательно сбой инициализации
в рантайме. Осуществимость на свежей БД подтверждай только на одноразовой локальной БД.
Нет её — сообщи runtime-часть как непроверенную; никогда не подменяй production-доступом.

## Границы отчёта

Для каждого пункта: severity, точный `file:line`, конкретный вход, факт, ожидание,
минимальная рекомендация и один статус: **подтверждённый дефект**, **гипотеза** или
**операционный риск**.
