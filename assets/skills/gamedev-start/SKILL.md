# Первая игра

## Когда использовать

Разработка игры с нуля: Godot 4 + Blender без интерфейса. Срабатывает, когда человек хочет сделать игру, спрашивает про Godot, Blender, геймдев, «сделай мне игру», «хочу свою игру». Не срабатывает для вопросов про чужие игры или прохождение.


Подстройся под человека. Если он не программирует — веди так, чтобы через
один вечер у него была игра, в которую можно поиграть, пусть из кубиков. Если
разбирается — обсуждай архитектуру и код на его уровне и не разжёвывай.

## Порядок работы (не нарушать)

1. **Сначала расспроси, потом делай.** Задай по одному вопросу, коротко:
   какой жанр (платформер, стрелялка, головоломка…), 2D или 3D, на что похоже,
   что главное в игре. Запиши ответы в `docs/game_spec.md` его словами.
2. **Проверь инструменты.** Выполни `godot --version` и `blender --version`.
   Если чего-то нет — объясни одной фразой, что это и сколько весит, и **спроси
   разрешения**, прежде чем ставить:
   - Godot: `winget install --id GodotEngine.GodotEngine --exact`
   - Blender (только если нужна 3D-графика): `winget install --id BlenderFoundation.Blender --exact`
   Не ставь Blender заранее — он большой, а для 2D не нужен.
3. **Играбельный кор на примитивах.** Сначала движение → враг или препятствие →
   урон → победа и поражение → перезапуск. Всё из простых фигур, без графики.
   Покажи человеку, как запустить, и дай поиграть.
4. **Только потом графика.** Модели в Blender — скриптом на Python, без окна
   Blender (`blender --background --python script.py`), экспорт в `.glb`.
5. **Только потом полировка.** Звук, меню, эффекты — в последнюю очередь.

## Правила проекта

- Каждый объект игры — отдельная сцена `.tscn`, чтобы человек мог открыть её
  в редакторе Godot руками.
- Структура: `godot_project/` (игра), `blender_scripts/` (генерация моделей),
  `docs/` (ТЗ и заметки).
- После каждого шага — запусти игру без окна
  (`godot --headless --path godot_project --quit-after 300`) и убедись, что она
  не падает. Говори «готово», только когда проверил.

## Как говорить

С тем, кто не в теме, — без терминов: вместо «инстанцировать сцену» —
«добавить врага на уровень». С разработчиком — его языком. Код в ответ не вываливай: скажи, что сделал, как запустить и что
дальше. Человек должен видеть прогресс каждые 10–15 минут, а не читать лекцию.
