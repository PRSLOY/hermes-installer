# Каталог дефектов: код, написанный агентом

Повторяющиеся, «урожайные» классы дефектов в коде более слабой модели или раннего
торопливого прохода. По убыванию ущерба.

## 1. Платформенный импорт на верхнем уровне модуля

`import fcntl` (только POSIX) наверху модуля, который импортируют десятки файлов, роняет
всё приложение при импорте на Windows — один `ModuleNotFoundError` кладёт всё ниже по цепочке.

Обнаружение: пройди по всем верхнеуровневым импортам; всё POSIX-only (`fcntl`, `pwd`,
`grp`, `termios`, `resource`), достижимое на Windows, фатально.

Фикс: ветвление на импорте.

```python
try:                      # POSIX
    import fcntl
    def _lock(fd): fcntl.flock(fd, fcntl.LOCK_EX)
except ImportError:       # Windows
    import msvcrt
    def _lock(fd): msvcrt.locking(fd, msvcrt.LK_LOCK, 1)
```

Асимметрия, которая кусает позже: `fcntl.flock` — на файловый дескриптор и снимается при
его закрытии; `msvcrt.locking` — на процесс и снимается при закрытии *любого* дескриптора
этого файла в процессе. Значит Windows-коду нужен **один долгоживущий дескриптор на
процесс**, а не открыть/закрыть на операцию, иначе блокировка тихо ничего не делает.

## 2. `except: return {}` на персистентном состоянии — тихая потеря данных

```python
try:
    return json.loads(path.read_text())
except (OSError, json.JSONDecodeError):
    return {}          # битый файл теперь неотличим от пустого
```

Следующая запись персистит этот пустой каркас — и все хранимые пароли, токены и ключи
пропали, без единой ошибки в логе. Самый разрушительный паттерн в каталоге.

Обнаружение: ищи широкие `except`, возвращающие пустой контейнер или `None` из функции
load/read.

Фикс: возвращай `(data, error)`; кидай выделенное исключение на порче; отказывайся писать;
делай бэкап до миграции.

## 3. Миграция, теряющая ключи верхнего уровня

`{k: v for k, v in data.items() if isinstance(v, dict)}` переклассифицирует каждый dict
как сервис и уносит остальное в `legacy`. Читатели, обращающиеся к `data["accounts"]` на
верхнем уровне, не находят ничего — данные в файле есть, но недостижимы. Симптом: «нет
настроенных аккаунтов», хотя файл ими полон.

Фикс: явный набор зарезервированных ключей, переживающих миграцию; идемпотентная миграция.

## 4. Объявленный, но никогда не вызванный обработчик

Хорошо написанная функция, которую никто не вызывает. Фича читается как реализованная и
мертва. Обнаружение: для каждого неэкспортируемого хелпера grep'ни места вызова. Ноль
попаданий вне определения — находка.

## 5. Общее имя temp-файла для атомарной записи

`tmp = target.with_name(target.name + ".tmp")` — учебная идиома атомарной записи для
**одного** писателя. При конкурентных писателях они сталкиваются, и `os.replace`
проигравшего кладёт обрезанный контент.

Фикс: уникальное имя на процесс (`f"{name}.{os.getpid()}.tmp"`), `flush()` + `os.fsync()`
до replace. На Windows оберни `os.replace` в короткий ретрай — транзиентный
`PermissionError` от антивируса или индексатора нормален.

## 6. Захардкоженный интерпретатор или POSIX-пути

`.venv/bin/python3` в доках и вызовах `subprocess`; на Windows это `.venv/Scripts/python.exe`.
Используй `sys.executable`.

## 7. Дублированное состояние с расходящимися именами

Два компонента адресуют одну запись под разными ключами (`state_<index>.json` против
`state_<login>.json`). Каждая сторона работает в изоляции; вместе не находят друг друга.
Выбери канонический ключ, второй оставь read-only fallback'ом на время миграции.

## 8. Неопределённое имя — гарантированный краш на одном пути

Ловит переименованную или удалённую переменную, срабатывающую на редкой ветке. Дёшево
найти, точно реальный дефект.

```bash
ruff check . --select F821 --output-format concise
```

Полезно и `F841` (неиспользуемые привязки) — иногда вскрывает забытую логику.

## 9. Файл, который не компилируется

`compileall` по репозиторию накопленных агентских черновиков регулярно вскрывает файлы,
которые ни разу не парсились, — автор их не запускал.

## 10. Зависимость заявлена, но никогда не проверена

Код, безусловно пробрасывающий прокси, sidecar или эндпоинт, который он никогда не
проверяет, превращает отсутствующую зависимость в мёртвую фичу. Хуже — падает как
несвязанная ошибка и читается как регрессия последней правки.

Случай: лаунчер всегда передавал `socks5://127.0.0.1:9090` в браузер, форвардер не был
запущен — автоматизация браузера не могла подключиться.

Обнаружение: для каждого захардкоженного URL/порта grep'ни проверку живости рядом с местом
использования. Нет её — это находка. Фикс: пробуй до использования и делай fallback;
тестируй обе ветки.

## Проход статической сортировки

```bash
python -m compileall -q . -x '(\.venv|__pycache__|\.git)'
python -m ruff check . --select F,E9 --statistics
python -m ruff check . --select F821 --output-format concise   # реальные баги
python -m pytest tests -q
```

`F821` и сбои компиляции — подтверждённые дефекты. Неиспользуемые импорты и предупреждения
f-строк в черновых скриптах — шум, не раздувай ими отчёт. Числа называй честно, а не «линт
чист».
